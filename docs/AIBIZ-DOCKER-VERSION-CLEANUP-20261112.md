# Aibiz Docker Version And Cleanup

Date: 2026-11-12.

Updated: 2026-11-13. Superseded counts and the v1 name-only inventory must
not be used as deletion gates. The corrected v2 inventory, checked-in image
lock and first two-alias cleanup are in `AIBIZ-RUNTIME-LOCK-20261113.md`.

## Why There Are Duplicates

The host contains several categories that must not be conflated:

1. **Current shared runtime**: the small set of containers currently serving
   the local stack.
2. **Owned isolated fixtures**: private `nf-<run-id>` networks and containers
   retained for runtime receipts. These are protected by ownership labels and
   cleanup receipts.
3. **Historical experiments**: `n01-r4-fix*`, `p04`-`p09`, `s07-*`,
   `plmweb-isolated-*`, compiler helpers and rollback probes. Most are stopped
   and exist only to preserve evidence.
4. **Image tags**: many UUID/date/`local`/`p03` tags point to different image
   IDs. Tags are not versions unless bound to an immutable receipt.

The earlier November 12 inventory reported:

- 36 aibiz-related running containers, including shared services and
  retained `nf-*` owned fixtures.
- 244 stopped or Created historical containers.
- 167 aibiz image tags.
- 155 unique aibiz image IDs.

Those values were scope-dependent and incomplete. The corrected November 13
inventory finds 12 shared plus 26 owned running containers and 247 stopped
related containers. The inventory tool itself never deletes anything.

## Version Policy

The correct version is the immutable receipt-bound image, not `local`,
`p03`, or the newest timestamp tag. Every promoted runtime must bind:

- source/package receipt SHA;
- image ID and architecture;
- deployment input SHA;
- runtime configuration SHA;
- owned network and peer inventory;
- browser/static served-byte receipt where applicable.

Recommended canonical bindings for future owned runs are the current source
package/image receipts generated by the run, with a unique run label. Do not
retag old images as `latest` or overwrite an existing tag.

## Safe Cleanup Order

1. Freeze the current running set and retain its inspect/configuration
   receipt.
2. Generate the immutable inventory:

   ```sh
   node scripts/audit-aibiz-docker-inventory.mjs \
     --output=.artifacts/aibiz-docker-inventory-20261112/report.json
   ```

3. Review only stopped candidates with no owned-fixture label, no retained
   receipt reference and no volumes.
4. Remove exact container IDs in a new cleanup receipt.
5. Remove unreferenced image IDs only after all tags, containers and receipts
   are rechecked.
6. Re-run the inventory and version ledger.

No cleanup command is part of the inventory script. This prevents broad
`docker system prune` behavior from deleting evidence, volumes or current
services.

## Current Recommendation

Do not delete the 12 shared running services or retained owned fixtures. The stopped `n01-r4-fix*`, `p04`-`p09`,
`s07-*`, `plmweb-isolated-*` and compiler-helper containers are cleanup
candidates, but they require a second ownership/volume/receipt audit before
removal. Historical images with duplicate content can later be collapsed by
deleting tags first and image IDs only when unreferenced.
