## B01 / L02：通知正文的最小源码缺口

权威产品模板内联在 `plm/model/PSSYSTEM.json` 的
`getAllPSSysMsgTempls`，四个产品模板渲染六个固定中文事件：

- `product_member_create`：把你加入了产品
- `product_member_remove`：把你移除了产品
- `product_archived_or_activate`：归档/激活了产品
- `product_remove_or_recover`：删除/恢复了产品

四个模板的 pilot 文本还直接包含 `产品管理`。`plm-web/src/locale/en.json` 已有
通用 `产品管理 -> Products`，但没有六个事件的英文词条；更关键的是，历史英文
手机回执的 `leafActions.event` 仍是上述中文，而 action title 为 `Mark as read`。
这证明控件双语已生效，持久化通知正文仍是中文；该回执属于显示层修复前版本。

当前候选的 web/mobile HTML provider 在 `parseHtml` 后调用新的
`localizeInternalMessageHtml`，再以 `v-html` 显示。该函数只处理
`.notice-card__event-desc` 的六个固定事件短语及 `.notice-pilot-info` 中的
`产品管理`，未知自定义通知、产品名称、编号、用户名称、时间和原始消息字节保持
不变。`plm-web/src/locale/model-locale.ts` 的 `localizeStaticHtml` 仍只处理
模型对象中 `contentType === 'HTML'` 的显示元数据，不接收 `IInternalMessage`。

最小安全修复形状是**显示层翻译**：按已知通知模板和固定 span 文本，只在英文显示
时替换事件短语及固定 `产品管理`，保留 product ID、产品名称、用户名称、时间、
emoji、HTML 结构和原消息 JSON/HTML 字节。桌面/移动两个 provider 使用等价纯函数
并由真实四格重新验收。直接修改 PSSYSTEM 模板会影响新发送内容、模板路由、
队列/历史消息和已有回执，不能在没有新数据集、多角色和新发布字节验收时直接做。
自定义通知或未知模板必须原样显示，不能用全局中文字符串替换。
