## Fresh 关闭条件

| 字段 | 必填证据 |
| --- | --- |
| `run` | 新 runId、实际开始时间、fresh owned inspection、执行时 active、资源身份 witness |
| `candidateBinding` | 执行/交付四仓库提交、相同受测源输入指纹、package/images 与 frontend served bytes、current-commit 回执；变化需 reviewed delta |
| `route` | 精确 `GET /ibizmodeling/appdata?psdevslnsys=$ROOT_ID`、已发布配置/源码绑定、原生 query -> AppContext；通用 `/appdata` 仅用于基础身份 |
| `http` | 12 authenticated 查询、4 有投影/8 无投影、2 匿名拒绝；正常身份链/20 秒 token 不变、无注入、真实 dispatch、全部错误、两模型库全行快照 |
| `browser` | zh-CN/en-US × desktop/mobile 四组；正常 UI 登录、原生投影消费、目标与稳定无 loader、无强制点击/控制器注入、全部错误计数 |
| `cleanup` | 精确 owned 资源退役、最终两模型比较、共享生命周期/配置及声明输入比较、无全局 prune/持久卷删除、无未解释 cleanup 错误 |

每个 scope 独立记录 NOT-RUN/IN-PROGRESS/FAILED/BLOCKED/VERIFIED-BOUNDED。
只有四个 scope、当前版本绑定与清理均通过，整体才可写
`VERIFIED-BOUNDED-BOOTSTRAP-ONLY`。空字段、false flag、只有 source receipt、
旧 `readonlyMetadataAcceptance`、缺失角色/视口、错误或已退役回执均不能得到通过。

契约测试只验证这套记账结构与 fail-closed 规则，**不是 native 验收签发器**；
它的受控正例不会写入基线。真实 flags 和回执必须由主协调核对私有原文后填写。
公共记录无需读出私有 payload；要审计哈希或重跑，必须恢复对应私有档案及精确版本输入。

填写时使用实际 receipt 的脱敏引用，不复制其 payload：

```js
run: {
  runId, startedAt, identityWitnessSha256,
  freshlyInspectedOwnedResources: false,
  activeAtDispatch: false,
  retiredBeforeExecution: false
}
receipt: {
  path, sha256, kind, runId, observedAt,
  sourceOnly: false, executed: false, retiredBeforeExecution: false
}
```

这些 false 是未验状态，不是等待批量置 true 的模板。Scope 的 receipt kind 依次为
`owned-native-route-binding`、`owned-native-routing-http`、
`owned-native-browser-bootstrap`、`exact-owned-cleanup`；
当前提交证明另用 `current-commit-source-byte-binding`。
每个 browser cell 需实际 `status` 和 `consoleErrors/pageErrors/failedRequests/blockedRequests`，
不能省略错误集合后得到零错误。`observedCoverage` 需与四项 requiredCoverage 精确一致。

即使基础 bootstrap 最终通过，以下值仍必须 false：完整 CRUD、48-role 矩阵、
全部中英文布局、UAA/metadata/cache 全状态不变、Unicode 已迁移/API通过、共享部署/发布、
全部 canonical 完成。当前 HTTP 工具的物理不变证据仅覆盖两模型库，不能扩成全部状态。
