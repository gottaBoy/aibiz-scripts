## 具体修复

独立审查发现融合读取的权限竞态：原 `readPinnedFile` 返回的是 open 前
stat。文件在 lstat 后、open 前从 0644 变为 0600，仍可由宿主所有者读取，
但容器不可读。新实现读取后重新核对当前路径的 `dev/ino`、普通文件类型
及最新权限。回归在该精确时点改变模式，不能以旧 stat 或哈希相等接受。

bridge 子进程现在要求七个明确验证模块的源码 pin 完整存在并匹配。
这些模块分别是 R05 overlay/generator、pinned 文件读取、model-context
overlay、Central 路由、owned context 和前端 preparation。该清单是局部
版本绑定，不声称覆盖所有传递依赖或防御任意宿主代码替换。

前端 prepare、launcher 和 worker 仍重新构造输入并核对实际候选、完整
模型树与 provider 的精确只读挂载。不能删除 R05 字段或仅相信 JSON 中的
成功标记来绕过检查。A01 的 ModelAPI 也只允许该可信覆盖层产生的修改，
没有扩大实体权限、改写 84 条原始案例或伪造根值。
