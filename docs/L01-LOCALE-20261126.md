# 业务模型文案中英文增量

检查点：2026-11-26，Asia/Singapore。范围为 L01/L02 的维护源码词条与模型执行回归，
不关闭任一顶层项。

## 手册要求

依据 [产品与项目](manual/PRODUCT-PROJECT.md)、
[测试与知识](manual/TEST-KNOWLEDGE.md)，工作项、迭代、发布、基线、评审、
测试执行和工时提示须保持明确业务语义：

- 结束迭代不表示全部未完成工作项自动完成。
- 删除工作项可恢复、删除模板不可恢复，以及删除用例同时移除未完成计划内执行用例，
  是不同的确认信息，英文不能简化为同一个“删除”。
- 设立基线、移出基线、移出迭代、取消普通关联和移除依赖应继续区分。
- 仅翻译显示属性，ID、字段代码、状态值、脚本、路径和用户输入保持原样。

## 本地实现观察

本轮编辑维护入口 `plm-web/src/locale/en.json`，新增 **96** 个明确英文词条，
另修正 **1** 个既有词条。它们来自当前实际发布模型中的字段标签、选择提示、
空态、操作按钮、确认和成功提示，覆盖：

- 工作项转换的原/目标类型与状态、影响数量、子工作项、依赖和关联。
- 迭代/发布的名称、目标、规划选择和开始/结束提示。
- 测试计划、执行人、执行结果、未测试/未执行、保存并下一条、评审意见与结果。
- 工时输入和空态、基线设立与移出，以及可恢复/不可恢复删除说明。

“结束成功”采用 `Ended successfully`，不暗示全部工作项完成。
测试用例实际 `level` 表单中的“请选择重要程度”使用 `Select Importance`，
与当前显示名“重要程度”的 `Importance` 一致，未将其技术字段或代码表改为英文键。
旧词典“选择重要程度”原为 `Select Priority`；本轮核对其全部 10 个实际消费模型，
均绑定 `level`、`plmweb.testmgmt__test_case_level` 与“重要程度”显示名。
因此将其统一修正为 `Select Importance`，并逐个执行真实模型回归。
其他既有词条未改写，实际“优先级”仍使用独立的 `Priority`。

新增 `plm-web/tools/tests/business-label-locale-20261126.test.mjs`。
测试执行当前真实 TypeScript 模型和维护本地化适配器，逐项比较所有标量；
只有声明的显示属性可以改变，中文模型与冻结的原模型保持一致。
特殊字符样例覆盖中文、补充平面字符、组合字符、引号、反斜线和换行。
没有改生成模型、插件源码/发布文件、共享 dist、运行配置或业务数据。

提交依赖复核发现，工作区早期修改已经让 `confirmMsg`、`successMsg` 参与翻译，
但原 HEAD 尚未包含这两项。最终仅提交显示属性集合的这两行必要增量；
`realTitle`、HTML/SVG 和 managed-picker 的其他既有适配改动保留在工作区。
因此下方 35/35 是当前工作区证据，不代替独立的干净提交复验。
