# L03 开放 DTO 文档契约实现（2026-11-28）

## 手册要求与验收边界

Development、API Reference、Data Model、Modeling IDE 是独立能力。本次只修复
API Reference 中两个实际存在但没有字段声明的 DTO 的结构表达，不关闭 L03 顶层项，
不把文档生成、JSON Schema 校验或旧回执视为部署后的业务接口验收。

开放对象契约不等于具名字段契约：不补充字段名、值类型、可空性、必填、校验或业务写入权限。
`customer_score`、`customer_score_precent` 仍仅属于单列的逻辑输出观察，不加入 DTO 字段。

## 本地实现观察

两个权威模型声明保持原样：

| DTO | 实际声明 | 文档结构 |
| --- | --- | --- |
| `idea_def_group_common_dto` | `DEFAULT` / `DE`，字段列表未声明 | 开放对象 |
| `view_theme_setting_usr1014979662dto` | `DEFAULT` / `DYNAMODEL`，显式来源 `Usr1014979662DTO`；系统 DTO 也未声明字段 | 开放对象 |

对应后端空 DTO 类均继承 `GroovyDTO`，其父类为 `EntityDTO`。
已审查的 `EntityDTO.reload` 复制未声明属性，`getAny` 经 `@JsonAnyGetter` 输出这些属性；
`DEMethodDTORuntime.isEnableAny()` 返回 `true`。`PSDEMethodDTOFieldImpl.isListMap()`
在缺少标记时返回 `false`，与 `EntityDTO` 的 DTOS 列表分支一起支持 `search_conds`
采用对象数组结构。

实现只接受上述两个精确模型声明及六份 SHA-256 锁定源码。系统 DTO 缺失、
来源声明改变、任一必要源码缺失或摘要漂移，均保留 `unresolved`；不会把任意无字段 DTO
自动当成开放对象。显式空字段数组继续采用原有声明语义。

每个开放 DTO 输出以下结构，并保留 `dto-fields-not-declared`；系统字段来源继续保留
`system-dto-fields-not-declared`。这些标记描述具名字段证据的缺口，与对象结构解析分开。

```json
{
  "type": "object",
  "additionalProperties": true
}
```

`search_conds` 的 DTOS 引用输出数组，`items` 为上述开放对象。明确 `listMap: true`
时输出对象映射，普通 DTO 引用保留对象结构。指向开放 DTO 某个具名字段的投影仍须找到
实际字段声明；不存在的字段仍报 `related-field-not-declared`。

中英文页面、锚点和全文搜索同时包含开放结构、字段未声明说明及源码依据。manifest
为六份新增输入记录路径、字节数和 SHA-256，沿用无符号链接、无硬链接及读取后二次核对的输入规则。

修改入口为 `plm/doc/tools/api-reference-dto.mjs`、
`plm/doc/tools/api-reference.mjs` 和 `plm/doc/tools/api-reference.d.mts`。
`local-documentation.ts`、权威模型、业务源码及部署服务未修改。

## 待决策/阻塞

本次证明的是精确模型及已提交后端源码的开放对象结构契约。尚未将候选生成器构建部署到
现有服务，也未证明运行 JAR 与这些源码逐字节对应。真实登录、写入/读回、授权、
语言切换、移动端和部署后嵌入文档仍需各自的本版本验收。

未来声明或源码发生变化时需重新审查并更新锁定摘要；不能为了消除 `unresolved`
放宽为“缺少字段即开放”。本次未拉取镜像、创建容器、重启服务、迁移数据库或执行网络请求。
