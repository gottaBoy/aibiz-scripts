## 2. What each acceptance gate still needs

The audit never awards a gate from a static inventory; unknown or unrun evidence fails closed.

- **source** - Complete editable source, provenance/license, pinned dependencies and local build entry; metadata or a src file alone is insufficient.
- **build** - Successful local source build with command, exit status, lockfile/input hashes and hashed output assets; prebuilt assets are insufficient.
- **load** - Real browser opens the built editor with its expected controls, no missing assets or unexpected remote dependencies; retain trace/network evidence.
- **coreEdit** - Exercise plugin-specific operations and validation on a real model with before/after assertions; a generic JSON/draft editor is insufficient.
- **save** - Persist the edit through the intended platform API and verify acknowledged model/revision; localStorage or download alone is insufficient.
- **reload** - A fresh browser/session loads the persisted model and preserves its semantics and revision.
- **platformIntegration** - Authenticated platform launch, permissions, real model/API contracts and runtime consumption are verified end to end without mocked services.

Runtime requirements the core audit enumerates:

- `exact-local-target-package`
- `source-build-receipt`

- `zero-unexplained-browser-errors`

## 3. Verification once the tarballs exist

The audit finds exact packages by scanning local roots, so a legitimately obtained
tarball only has to reach one of them. No network is used by the audit itself.

```sh
# from a directory that has the tarballs, e.g. obtained via the intranet registry
cd scripts
node harness-modeling-core-audit.mjs \
  --npm-cache ~/.npm/_cacache \
  --pnpm-store ~/.local/share/pnpm/store \
  --directory ../vendor-upstream \
  --container modelingweb
```

Exit code 0 means every exact asset was found; 1 means gaps remain, 2 means the
audit itself was incomplete. Re-run `node scripts/report-core-exact-gaps.mjs`
afterwards to confirm this list is empty.

## 4. What cannot be closed on a single workstation

The `load`, `coreEdit`, `save`, `reload` and `platformIntegration` gates need an
authenticated platform session. In this workspace interactive login is not possible
for the vendor deployment either, because authentication delegates to the external
UAC/CAS endpoints (`cas.ibizcloud.cn`, `192.168.100.5`). Those gates therefore need
the same intranet access as the registry, not just the tarballs.

Substitution is explicitly out of policy: other package versions, metadata, bundled
host libraries and PLM business plugins do not satisfy an exact core reference, so
this gap must stay open until the authentic assets and an authenticated platform are
available.
