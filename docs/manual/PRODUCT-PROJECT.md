## 一、必须保持的业务不变量

### PP01 产品、项目及成员边界

- 产品和项目创建均分为基本信息与成员确认两步。所属、名称、可见范围、标识、描述及确认后的成员集合须一起核对；创建成功后的详情必须指向新对象，而非仍展示旧选择。
- 列表应支持分组访问、搜索/分类、排序、星标；星标不能改变对象所属或成员权限。
- 产品设置覆盖成员与角色、工单标签、工单类型的全局类型选入/移除、组件开关、基本信息、移动、归档/激活、删除/恢复、需求/工单回收站。
- 项目设置覆盖成员与角色、工作项本地类型配置、组件、扩展属性、基本信息、移动、归档/激活、删除/恢复、工作项回收站。
- 项目类型必须区分 Scrum、Kanban、瀑布，不能把菜单或数据类型混成一个统一看板。切换组件可见性不等于改变后端权限。
- 项目集可以容纳项目和子项目集；一个项目允许属于多个项目集，也允许不加入项目集。成员与可见范围必须按项目集自身设置核对，不能以加入项目集隐式授予全部子项目权限。

### PP02 需求池、客户、工单和排期

- 产品需求应覆盖创建、列表/详情编辑、模板下载后导入、按范围导出；子产品/模块负责分类，不能仅在前端隐藏非当前模块数据。
- 排期先建计划，再从产品需求池选择范围，并按评估标准规划。正文没有给出评审状态机或统一评分公式，不能凭概述补出“已实现自动评审”。
- 需求可关联客户、其他产品需求、工单、项目工作项及测试用例；可从选择器搜索现有对象，或创建新对象后关联。关联不是复制对象或变更对象归属。
- 客户重要程度对应分值为：非常重要 3、重要 2、一般 1、不重要 0、未知 1。测试必须覆盖“未知不等于 0”和分布/总分随等级变化。
- 工单支持公共/个人分组、创建、详情编辑、模板导入及导出；工单可关联工作项、产品需求，并通过客户沟通添加回复。
- 客户支持分组/类别、创建、详情编辑、模板导入及导出。从客户侧选择既有工单时，正文限定候选为尚未指定客户的工单；从工单属性侧可以设置客户。重新归属的冲突处理须另行确认。
- 产品/项目可关联知识空间、打开关联页面和取消空间关联。取消关联不得等同于删除空间或页面。

### PP03 基线固定版本与比较方向

- 产品基线收录需求版本；项目基线收录工作项版本。版本选择应被持久化，不能仅存对象 ID 后每次改读最新内容。产品需求规划明确允许最新或历史版本。
- 基线建立完成后，内容不得再修改。后续对象编辑、新版本创建或版本恢复均不能改变已经固定的基线内容。
- 产品基线仅选择当前产品内其他基线，项目基线仅选择当前项目内其他基线；不能将跨产品/跨项目 ID 当作合法比较侧。
- 必须命名两侧：`A = 当前基线`，`B = 选择的比对基线`。新增/删除按侧别定义，不按日期新旧猜测。

| 集合/版本关系 | 手册显示含义 | 验收断言 |
| --- | --- | --- |
| `B` 独有对象 | 绿色，新增 | `B - A`，不是当前侧独有 |
| `A` 独有对象 | 红色，删除 | `A - B`，不是比对侧独有 |
| 两侧同对象、版本不同 | 黄色，修改 | 用对象身份配对，再核对版本 ID |
| 两侧同对象、同版本 | 相同 | 不得误报版本差异 |

- 比较动作应只读，不得执行同步、恢复或覆盖。交换 `A/B` 后，新增/删除应互换，修改仍为修改。
- 两侧共同对象可进行版本内容比较；需求版本比较支持隐藏相同项，工作项版本记录也支持隐藏相同属性。详情中的基线字段展示当前版本最近规划的基线及其状态，不能误指向别的版本。
- 版本记录包含初始化版本、按当前内容建立新版本、编辑版本名称/备注、最新与所选版本的属性比较，以及按选定历史版本恢复。编辑版本描述不等于编辑历史快照内容。

### PP04 工作项类型、父子关系、复制和移动

- 工作项是统一协作对象，但类型有各自语义：史诗、特性、用户故事、需求、缺陷、任务、事务。类型存在不表示所有项目都允许所有类型。
- Scrum/Kanban 正文规定史诗下面可加特性、特性下面可加用户故事、用户故事下面可加任务/缺陷；瀑布的子类型由项目配置决定。添加子项支持新建和选择既有项。
- 树状/平铺只改变展示，不应改写父子关系。普通关联关系与父子关系必须分开保存和展示；取消普通关联不能删除对象。
- 复制父工作项时同时复制其子工作项；新树应有独立身份并连接到新父项，原树不变。手册不保证所有状态、评论、版本、工时或关注人全部原样复制。
- 移动父工作项时同时移动子工作项，弹窗允许选择目标项目和父项；移动后应检查整棵子树的项目、父项、根引用和目标类型规则。不能只移动列表第一行。
- 仅可独立存在的类型可以解除父子关系，不能把“取消关联”当作所有子类型均可脱离父项的承诺。
- 工作项支持单个/批量归档、从归档视图激活并选择父项、单个/批量删除、从项目回收站恢复。归档与删除是不同生命周期，不以名称相似共用错误状态。

主要来源：`7e93d764f45399a61fefba80e0d44e7d`、`4405b04f6da192fd12924365e59db1bd`、`c27dd6db5f1771c3de8dc878c75d3654`、`95944401f4b7a5985ea6a293ffa87d80`、`080f35a001a07cab6f76f9cb28afa016`。

### PP05 Scrum 冲刺、进度和未完成项

- 敏捷规划以史诗/特性/用户故事分解价值；故事点是复杂度/工作量估计，不得无说明自动等价为小时。
- 迭代可按类别/分组管理，具备名称、项目、负责人、开始/结束日期、目标等信息；开始迭代后跟踪列表属性、完成数量、成员贡献、燃尽和关联发布/测试计划。
- 完成迭代有未完成项时，必须由确认操作明确选择以下处理，不能静默丢弃或默认全部完成。

| 用户选择 | 应观察到的结果 |
| --- | --- |
| 转到待分配工作项 | 未完成项离开原迭代，进入待分配范围；不因转移改变为已完成 |
| 转到其他未完成迭代 | 未完成项改属所选目标迭代；目标不能是已完成迭代 |
| 将未完成项全部完成 | 被处理项按完成规则转状态；原迭代结束；不得误改不属于该迭代的项 |

- 取消确认应保持原状态与归属。测试需分别覆盖全部已完成、混合状态、没有工作项、三种选择、非法目标和重复确认。
- 发布不是每轮迭代的必然结果；一个发布可关联多次迭代。迭代的测试计划由测试管理侧关联，本页的概览是读取入口。

主要来源：`35585866fda9b9618310912347902d71`、`9a632665d6452103d2725e969c011105`、`b9267f0d975fba08e59c097c56cba6dc`、`fc453c75a1cf48dcecac94b2e4efc580`、`4cd3d5351e98c7d9ab479674936eea5b`。

### PP06 Kanban

- 看板由状态列与泳道帮助可视化工作；正文涉及 WIP、WIP Limit 和 DoD 概念，但没有定义本地超限阻止策略，不能自行写成“已强制执行 WIP 限制”。
- 看板支持创建、重命名、删除、创建工作项、列内快速创建、跨列拖动和全屏；跨列动作须核对实际状态变化与权限。
- Kanban 工作项组件复用 Scrum 的列表/视图管理能力，并支持事务类型。正文中“复制看板 TODO”仍是未完成说明，不作为已明确的复制规则。

### PP07 甘特、瀑布计划、里程碑与交付

- Scrum/Kanban 路线图显示需求排期；可从编号打开详情，搜索/筛选类型，编辑开始/截止时间、定位今天、切换时间轴和全屏。
- 整段甘特条平移应同时改变起止点并保持时长；不要把拉伸边界与整段平移混为同一种断言。持久化后重新打开详情/刷新再核对，不能仅看像素移动。
- 瀑布项目以计划分解工作，可增加子工作项、编辑负责人/进度/时间、查看/删除计划、关联工作项，管理交付目标和交付物。
- 里程碑可从独立组件、规划或计划子项入口建立，可编辑标题/状态/负责人、导出 Excel、管理交付和删除。
- 交付目标与提交的文件是不同对象：创建目标后提交交付物，目标可编辑/删除；必须核对目标所属计划/里程碑、文件归属和实际可下载内容。
- 术语解释了依赖关系，但操作页没有给出依赖类型、自动调度、循环依赖、工作日或时区计算规则。不要把这些未定义项写成已经实现。

### PP08 资源、容量与工时

- 项目资源只统计当前项目；项目集资源汇总其中多个项目。加入两个项目集不应在同一集合口径内重复计算同一个工作项。
- 资源视图可以添加成员/部门团队，展开其工作项，选择日/周/月/季度/自定义区间，以及按预估工时、剩余工时、工作项数量计算容量。
- 每日容量与工作日是独立配置。手册颜色含义是未满为浅色、饱和为绿色、超出为红色；验收要比较数值和状态，不只比较颜色。
- 调整工作项排期后重新加载，核对日期与容量同步更新；筛选/类型切换要一致应用到明细与汇总。
- 工时从工作项详情登记，可选择子工作项；登记后查看进度、当前用户概览、成员日期/项目统计、筛选日志与导出。
- 容量不等于实际工时；工时概览不等于所有成员总工时。父子汇总必须说明是否包含父级直接登记，避免二次合计。负数、零值、精度、跨日、撤销/修改权限是建议边界测试，正文尚未定义全部规则。

### PP09 发布、跨产品追溯、筛选与报表

- 发布具备名称、项目、负责人、开始发布时间及分组/类别；支持编辑/删除、阶段变更、概览、日志、关联迭代、测试计划与规划发布工作项范围。
- 关联迭代和直接规划工作项是不同入口，不能假定二者自动并集、去重或自动发布，必须用具体范围核对。
- 项目工作项可关联/解除产品需求、工单、测试用例；支持搜索、筛选、最近浏览及新建后关联。需要从双方入口回读同一关系。
- 迭代/项目关联测试计划应与测试管理侧操作保持一致；关联知识空间时只建立关系，不拷贝/删除页面。
- 筛选器组合条件跨项目查找工作项，支持分组创建/改名/删除及条件保存。跨项目查询仍须受可见范围约束，不能因为是筛选器就绕过对象权限。
- 报表必须覆盖 14 类结果：团队速度、迭代燃尽、成员负荷、需求属性/状态/每日趋势/累积流/年龄、缺陷属性/状态/年龄/每日趋势/未解决累计趋势/回归分布。每张报表需有源记录、筛选范围、边界日期、非空与空态对照，不能仅验收图表渲染。

主要来源：`7a5827ef214bfc1347cf23a34f40035a`、`9646fde73a3c8b6bd100a5a6a3df3dfe`、`f07cf80bd5a22ee3084c10990c4ab87a`、`199cc9994ca51c152b8e852ca21f136c`、`a1045643e2f893cc3f02502dc0d4da51`、`8e0d6eadd1475b4fc4b2118f896e08be`。

### PP10 协作与通知

- 工作项详情具备评论/回复、`@` 成员、`#` 工作项提及、复制编号/链接和附件管理；链接应指向相同对象，接收者权限仍需独立验证。
- 通知矩阵必须分别测试“评论提及我”“状态变化”“普通操作”，不能以关注记录存在推断消息已送达。

| 模式 | 是否保持关注 | 正文定义的通知范围 |
| --- | --- | --- |
| 不关注 | 否 | 评论中被 `@` 时 |
| 订阅 | 是 | 评论中被 `@` 时 |
| 重要通知 | 是 | `@` 与状态变化等重要事件 |
| 关注 | 是 | 全部通知 |

- “不关注”不等于完全不接收 `@`；“订阅”与“不关注”的通知范围文字相同，但关注关系不同。外部客户沟通的可见范围不得默认为内部评论的可见范围。

主要来源：`c95cd4bab513c0f7129815a0c474e7c2`、`a6f13a1e7132ae0dbab06174322ae8c3`。

## 二、多角色全流程与负向验收

以下是测试角色，不是本分片对官方权限表的补写。先由管理员手册/本地角色配置确定每个角色的允许操作；权限未明确时标记待确认，不用管理员代跑普通用户。

建议数据：两个互不可见的产品、两个互不可见的项目，以及 Scrum/Kanban/瀑布各一份；有权限的产品负责人、项目负责人、普通执行成员、只读成员、非成员、外部客户。对象名称和 ID 应唯一，保存操作前后实体与关系快照。

| 场景 | 角色与执行顺序 | 成功断言 | 负向/恢复断言 |

## 四、手册 TODO、歧义与开发前确认

1. **看板复制尚无规则**：`0bf07568627906c7b9cc72e9f76374a7` 明确带 TODO；先确认复制栏、泳道、筛选和工作项的范围，不能默认深复制。
2. **迭代时长文字不一致**：术语页同时出现 1-4 周与通常 2-4 周；不应实现为未经确认的硬限制。
3. **创建用户故事与迭代先后**：术语称先有迭代才能选择，工作项创建页未说用户故事必须属于迭代，且结束可转待分配；不要误加“无迭代禁止创建”约束。
4. **完成态值需映射**：手册只规定全部标记完成，本地节点直接写状态 40；项目本地工作流、自定义类型和缺陷是否统一该值需验证，不能按文案推定。
5. **结束迭代的原子性**：模型先更新迭代状态再处理工作项；是否同事务、半失败/并发/重复请求如何处理须补真实证据。正文未规定目标迭代的同项目校验细节。
6. **基线不可变范围**：正文禁止改内容，但未细分基线名称/备注、删除基线、关系移入移出、固定版本内容、历史版本恢复等接口；冻结规则必须在后端全部内容变更入口验证，不能只禁用按钮。
7. **基线规模与版本**：本地设立模型的关系查询上限是 10000；超量、历史版本、删除对象和版本提交失败不得靠截断或重选最新掩盖。产品页显式支持历史规划，项目页没有同样详细步骤，需核对 UI。
8. **父子复制范围**：手册要求带子项，但未声明归档/删除子项、评论、工时、历史版本、附件实体与二进制的保留规则。当前模型的状态重置和默认关注应形成已评审字段表。
9. **移动和解除关系**：目标项目类型不兼容、原父权限、后代循环、编号/根引用/迭代/发布跨项目清理规则均未充分定义；不能只凭“移动成功”消息验收。
10. **甘特规则**：时区、夏令时、工作日/自然日、单边日期、日期精度、依赖联动、父子日期汇聚和冲突处理未完整规定；整段平移保持时长是明确要求。
11. **容量/工时口径**：跨项目集重复项目、假期、缺省工作日、零容量、剩余工时分摊时点、登记修改/删除对实际/剩余/父级的影响需另列公式和样本。废弃汇聚逻辑不能当当前行为依据。
12. **通知渠道与范围**：两种仅 `@` 模式只在关注关系上有区别；手册未说明外部邮件/消息渠道、重试/去重/时延、离组成员与客户的权限。关注控件不证明送达。

14. **稀疏与转引页面**：项目设置“项目组件”只有标题；项目集工作管理正文简短；项目集设置页面提示文字混用项目；测试计划关联转到测试管理说明。需对接管理员/测试分片，不补造细节。
