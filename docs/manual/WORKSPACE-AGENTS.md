# Aibiz Workspace Agent Instructions

## 范围与事实边界

- 此工作区包含多个独立 Git 仓库，公共根不是 Git 仓库。先读目标仓库状态，保留用户及其他 agent 的修改；只提交本任务所属文件。
- 用户要求本地化完整能力并支持中英文。不要将页面能打开、源码存在、空数组 HTTP 200、控制器注入或旧回执当成功能完成。
- 官方使用手册规则见 `scripts/docs/manual/README.md` 和三个领域指南；125 页索引见 `scripts/docs/manual/chapter-index.json`。本规则基于 2026-11-13 快照，整理于 2026-11-14；800 张独立图片尚未逐张核验。
- 将结论分为 `手册要求`、`本地实现观察`、`当前版本验收证据`、`待决策/阻塞`。手册本身的 TODO/开发中不是承诺已提供的能力。
- 业务任务状态以 `scripts/docs/ALL-TASKS-20261111.md` 为检查点；先核对新证据再更新，不批量勾选完成。手册学习不会关闭 B/M/A/L/D/K/O 能力项。
- Development、API Reference、Data Model、Modeling IDE 是独立能力，不在该手册目录内；MQTT 实时日志也需独立端到端验证。

## 仓库与修改入口

| 路径 | 责任与检查点 |
| --- | --- |
| `plm/model/` | PLM 领域、视图、操作、权限、流程及报表模型；优先查权威模型而非只修生成页面 |
| `plm/backend/plm-core/`、`plm-provider/`、`plm-util/` | 后端实体/服务、接口与逻辑；联查模型及数据库迁移 |
| `plm/deploy/compose/` | 服务配置、初始化和迁移；注意 Compose 文件合并顺序及持久化 |
| `plm-web/src/publish/`、`src/model/`、`src/runtime/` | PLM 前端与模型运行行为 |
| `plm-web/src/locale/` | 英文词条及模型/代码表/布局等本地化适配 |
| `plm-web/public/plugins/`、`plm-web/dist/`、`plm-web/start.sh` | 插件发布与实际服务字节；启动复制及覆盖顺序不能忽略 |
| `modelingweb/app/`、`modelingservice/` | Modeling UI、IDE、平台服务；不能用 PLM 导航代替原生 CRUD 验收 |
| `ibiz-app-hub/`、`ibiz-service-hub/` | 共享前端运行时/组件与后端平台；改动影响多个产品，应扩大回归 |
| `plm-e2e/`、`scripts/tests/` | 浏览器流程与工具/源码契约；测试通过范围必须明确 |
| `scripts/docs/`、`scripts/records/` | 待办、证据说明、运行锁和资源保留清单；原始私有证据不提交 |

命名层可能不同：API/模型 `article_page` 对应物理表 `PAGE`。按真实嵌套路由验证，
不要将裸 `/comments` 的 404 当作页面评论接口不可用，也不要伪造路由以得到 200。
生成文件的来源与构建命令应一起记录；只改生成结果不能算可重复修复。

## 领域指南与不可破坏的规则

产品、项目任务先读 `scripts/docs/manual/PRODUCT-PROJECT.md`：

- 需求/工单/客户和跨资源关联必须保留归属、可见性、成员、版本及生命周期语义。
- 已设立基线不可变。比较目标独有为绿色、当前独有为红色、版本差异为黄色，不能反转。
- 冲刺结束需显式决定未完成项去向，不默认全部完成。复制/移动工作项应处理子项及目标项目合法性。
- Scrum、Kanban、瀑布流程不混用；甘特整体平移应保持时长，容量必须考虑工作日、成员日容量及统计范围。

测试、知识任务先读 `scripts/docs/manual/TEST-KNOWLEDGE.md`：

- 历史用例恢复生成新版本；完成评审不得通过普通状态变更重开；仅活动阶段的指定评审人可提交该阶段结果。
- 测试基线引用最新用例版本时的自动创建版本规则是测试领域特例，不外推到全部基线。
- 重复执行不能重复增加计划报告分母；执行状态、步骤实际结果、缺陷与版本要能追溯。
- 草稿自动保存与发布分离，公开分享不得泄露草稿。锁定页面不能被管理员直接绕过编辑，必须先走有效解锁。
- 只读空间成员可以关联页面到资源，但不能修改正文。撤销、过期、密码、子集分享均需真实匿名回归。

管理、集成、度量、协作任务先读 `scripts/docs/manual/ADMIN-INTEGRATION-METRICS.md`：

- 一个组织所有者，多管理员按授权管理；子产品管理员没有隐式组织管理权限。全局模板与对象局部配置分开。
- 手册第三方集成范围为钉钉/企业微信。外部同步不自动创建 PLM 用户；钉钉匹配手机号，企业微信需明确用户绑定。
- 真实配置后验证同步与消息投递、失败和撤销；模拟响应/仅保存表单不算集成完成。不要提交 AccessKey、SecretKey 或用户绑定隐私。
- 保留指标原公式及分母；DI 权重为 10/3/1/0.1，估算偏差是逐项绝对相对误差的均值，不是汇总值的相对误差。
- 测试执行率为至少执行一次的用例/计划全部用例，通过率为最新通过的用例/计划全部用例；重复执行和零分母另作明确决策。
- 协作主题/讨论不等同完整目标/OKR 能力；系统预置属性/状态不可删除。

## 中英文与 Unicode

- 业务文案、空态、错误、弹窗、代码表、插件、嵌入 IDE 和格式化输出都要覆盖 `zh-CN` / English；切换、刷新、深链接和移动端均需验证。
- 不翻译或改写持久化 ID、字段代码、权限值、状态存储值和 API 路径；不能用英文标签替换数据库键来掩盖本地化缺失。
- 中文、补充平面字符/emoji、组合字符、引号、反斜线和换行应无损往返。使用参数绑定和上下文输出转义，不删特殊字符、不双重编码。
- PLM schema 的 mb4 修复见 `scripts/docs/PLM-UNICODE-FIX-20261113.md`；不能由此推断平台 `ibizapi` 或其他库已修复。数据库变更需备份、克隆恢复、元数据/数据一致性、幂等及真实 API 验证。

## 多角色全流程验收

先用真实配置的账号建立最小自有数据集，角色至少包括：组织所有者、受限组织管理员、
子产品/对象管理员、普通成员、只读成员、非成员、跨组织用户和匿名分享访问者。
分配评审人及外部身份映射时另测对应角色。不能仅靠前端按钮隐藏判断授权。

每条流程检查：创建 -> 分配/关联 -> 合法状态迁移 -> 版本/执行/发布 ->
报表/通知 -> 刷新与跨角色读回 -> 归档/删除/恢复或撤销 -> 清理自有测试数据。
同时验证无权、跨租户/根、篡改关联 ID、非法状态、过期分享与错误重试，确认拒绝后无持久化副作用。

- 浏览器测试记录 console error、未处理 Promise、失败网络请求及业务响应；先解释预期拒绝，不忽略实际异常。
- 需要验证真实用户操作、持久化读回、关联完整性、版本、报表和权限。不得通过强制点击、控制器注入、共享 SQL 写入来绕过前置失败。
- 回执绑定代码提交、模型/配置及静态资源哈希、镜像 ID 和挂载输入、语言/视口/角色、命令、结果、清理结果。图片或历史回执不能替代本版本验证。
- 先运行有针对性的轻量测试。文档检查命令为 `node --test scripts/tests/plm-manual-reference.test.mjs`，不触发 Docker。
- 全量 `scripts` 测试存在可能启动依赖服务的测试。先审命令及资源预算；长时间无输出时保留进程/阶段诊断，不反复叠加运行，也不把终止写成通过。

## 资源与运行安全

- 只处理可证明属于 aibiz 且本任务允许修改的资源；不操作其他项目，不删持久卷或 bind 源目录，不运行全局 prune。
- 运行基线/镜像锁见 `scripts/docs/AIBIZ-RUNTIME-LOCK-20261113.md` 和
  `scripts/records/aibiz-image-retention-20261113.json`。锁的是已观察基线，不是“最新正确版本已验收”。
- 2026-11-13 已退役历史/隔离容器，旧资源回执不代表容器仍在。需要时只建一套明确自有的验证环境，验证后归档并清理，不重建数百个环境。
- 镜像锁不涵盖宿主机挂载代码/JAR/模型/启动脚本；上线需核对真实服务字节、插件覆盖顺序和回滚输入。
- 未经当前任务范围和恢复计划支持，不重启/替换共享服务、不迁移共享库、不将开发候选推为运行版。
- MQTT 当前部署显式禁用；不能只隐藏提示或打开开关就称日志完成，需验证认证、WebSocket/代理、订阅权限、发布和断线恢复。
- `.artifacts/`、数据库备份、令牌、账号密码、业务数据、请求头及原始抓取文件保持私有；只提交脱敏摘要和可重复的契约。

## 协作与交付

- 多 agent 只在用户或适用规则明确要求时启动，给出独占文件边界；避免多人改同一文件，不在其他 agent 编辑时做全量暂存。
- 先列差异/待办，逐项补证据再关单。手册 TODO、矛盾和本地失败记录在
  `scripts/docs/manual/VALIDATION-BACKLOG.md`，不要编造剩余数量或完成率。
- 修改后运行覆盖本次风险的测试并检查 `git diff --check`；明确未运行的测试及阻塞原因。
- 提交和 push 按用户当前授权执行：只 push 已审查的本任务提交，保留其他仓库脏工作区；失败如实报告。
- 本文件的受版本管理副本为 `scripts/docs/manual/WORKSPACE-AGENTS.md`；
  工作区根 `AGENTS.md` 与副本同步维护。
